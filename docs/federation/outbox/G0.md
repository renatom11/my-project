## Tier 1 — general candidates (target: core `docs/LESSONS.md`)

### LC-01 — an enumerated-identity check that validates one value

**Rule.** A self-identification check that validates only one value of an
enumerated identity gives false assurance for every other value. Either
scope the check to all values of the enumeration, or state its coverage
at the point where its result is read.

**Incident.** A repository template records its own identity in a state
file: a role field drawn from a fixed enumeration of four values, and a
field naming the repository's own canonical URL. When a copy is made, the
copy inherits both fields from its parent and is required to rewrite them
as its first act; a copy that has not done so is, by definition, not yet
founded, and its inherited identity is wrong.

A continuous-integration check was written to catch exactly this: it
compares the recorded URL against the actual remote and fails when they
disagree. But it was written during a period when only one of the four
role values was in play, and so it was scoped to fire only when the role
field held that one value. The other three values were never checked.

A copy was later taken while the role field held one of the unchecked
values. Its recorded URL named its parent; its actual remote named
itself. The check ran and passed. CI was green across the entire history,
on a repository whose own state file asserted it was a different
repository. The condition was found only because a human-readable
bootstrap document instructed the reader to compare the two fields by
hand — the machine check that existed for this exact purpose was silent.

The fix is not to add a fourth special case. It is to key the check on the
comparison that actually matters — recorded URL versus actual remote —
independent of which enumeration value the role field holds.

**What breaks without the rule.** A verification whose scope is narrower
than its apparent subject reads as broader assurance than it provides.
Downstream readers see a green check named for the general property and
conclude the general property holds. Work then accumulates on the
unfounded copy — commits, records, downstream copies — and the identity
error surfaces much later, when unwinding it is expensive rather than a
one-line edit. The failure is silent by construction: the check does not
report "not applicable," it reports success.

**Now lives in.** Narrative only at the source; the corresponding
machine fix is queued as law-debt in the shell that authored the check.

### WS-01 — verify the simulator implements the testbench features the plan assumes

**Candidate rule.** Before a verification plan binds to a testbench
technique, confirm the chosen simulator implements it. Constrained
randomization and four-state simulation are commonly absent from
open-source simulator lanes, and a plan written against them has to be
rewritten once the lane is fixed.

**Failed criterion — LH1 (provenance-pinned).** No incident. The gap was
identified while digesting intake material, before any test existed, so
there is no incident commit or adjudicating packet to cite. The candidate
is anticipatory, and an anticipatory rule cannot clear a bar that asks
what actually broke.
